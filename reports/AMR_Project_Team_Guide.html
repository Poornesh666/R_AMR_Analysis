Antimicrobial Resistance (AMR) in Europe
Academic Project Submission Guide & Walkthrough

Goal of this Document: This document is designed for your 5-member team. It explains exactly what we built, why we built it, how the code flows, and provides a perfectly equal work-split justification to present to your professor.

1. What We Did & Why We Did It

What we did: We analyzed historical European dataset records from 2013-2014 to track the evolution of Multi-Drug Resistance (MDR). We built a data science pipeline that automatically extracts messy Excel files, runs an advanced Mixed-Effects Regression Model, and hosts a live, interactive web dashboard to display the findings.

Why we did it: Antimicrobial resistance is a severe global health threat. Analyzing raw geographical data demonstrates advanced data processing capabilities, while using mixed-effects regression proves we can handle mathematically complex, nested data structures (like variations between pathogen families and geographical regions) rather than relying on overly simplistic line charts.

3. Project Structure & Code Flow

If the professor asks how the project executes from start to finish, explain this 3-step pipeline:

  1. The Foundation (data_preparation.R): The script loops through the Dataset/European/ directory. Using Regular Expressions (Regex), it filters specifically for files beginning with percentage- (to ignore non-MDR isolate counts). It extracts the pathogen name and year dynamically from the folder naming structure, cleans empty rows, and outputs merged_MDR_data.csv.
  2. The Analysis (amr_regression.R): This script reads the clean CSV. It applies a Linear Mixed-Effects formula: Resistance ~ Year * Pathogen + (1 | Country). Finally, it outputs the ANOVA statistical summary into the reports/ folder and saves the visual chart into the plots/ folder.
  3. The Presentation (app.R): This is the Shiny Dashboard. It bypasses local static files and provides a dynamic User Interface wrapped in a modern Bootswatch theme, allowing end-users to manually filter the resistance datasets and view our interpreted epidemiological insights.

4. Which R Packages We Used & Why

It is critical to explain your technical decisions. If asked why a specific package was chosen, use these justifications:

  • readxl & stringr: Used for data ingestion. readxl natively handles Excel formats (which our raw data uses), while stringr allowed us to programmatically isolate the year and pathogen names from lengthy directory paths.
  • dplyr: Used for data manipulation, particularly the bind_rows() function which rapidly combined dozens of fragmented pathogen dataframes into a single pipeline.
  • lme4: The core of our statistical modeling. Standard linear regression was inadequate because European countries have vastly different baseline medical interventions. lme4 allowed us to assign "Country" as a random intercept grouping, preserving the integrity of the overall temporal trends.
  • ggplot2: The gold standard for academic data visualization in R. We used its stat_summary() function mathematically to calculate and draw Standard Error confidence intervals dynamically, rather than hardcoding static line charts.
  • shiny & bslib: Used for the web application deployment. shiny allows R to operate as a backend web server, and bslib securely overlays a modern, responsive HTML/CSS UI framework (the "Flatly" theme) making the dashboard aesthetically professional.
